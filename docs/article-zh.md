# 零依赖 CLI 数据管道 + Agent Skill 视觉交付：air-chart 架构实践

> 从一个真实问题出发：当用户在 Agent 对话里说"对比东京和首尔过去 7 天的 PM2.5 走势"时，
> 背后需要一条怎样的链路，才能在 **3 秒内** 交付一张专业、可嵌入、单位准确的矢量图表？

## 一、问题定义：Agent 时代的"最后一公里"是视觉交付

大模型已经能流畅地调用 REST API，但空气质量这类时序数据有一个天然矛盾：

- **API 返回的是嵌套 JSON**（OpenAQ v3 的小时/日聚合端点），在对话里直接贴出几十个点既不直观也不可读；
- **传统可视化方案太重**：Python + Matplotlib 意味着虚拟环境、依赖安装、字体配置——这与 Agent Skill "开箱即用、零状态" 的直觉背道而驰；
- **数据是"脏"的**：全球监测站运维水平不一，僵尸站点、传感器故障尖峰、缺失时间槽都是常态；
- **单位容易误导**：OpenAQ 返回的是物理浓度（µg/m³），不是 AQI；部分北美站点臭氧甚至返回 ppm——直接叠加 WHO 基准线会造成量纲错误。

air-chart 的答案是：**纯 POSIX Shell 数据管道 + 手写 awk SVG 渲染器**，把整个闭环压缩到 5 个脚本、零重型依赖。

## 二、管道架构：四个阶段，各管一段

```text
自然语言查询
   │  geo_resolve.sh     城市名 → 坐标+时区（200+ 内置城市库，坐标直传兜底）
   ▼
openaq_client.sh      OpenAQ API v3 封装：鉴权 / 缓存 / 退避 / 站点优选
   ▼
data_transform.awk    清洗（负值、超物理上限尖峰）/ 断点检测 / 统计聚合
   ▼
render_draw.sh        纯 awk SVG 渲染：折线 / 柱状 / WHO 基准线 / 图例
```

### 1. 站点优选：宁可少画，不可画错

直接按城市名调 API 常返回两类坑：已废弃多年的旧站点、同名异地城市。air-chart 的策略是"坐标优先 + 活性过滤 + 参考级加权"：

- 内置 `top_cities.tsv` 把城市名解析为经纬度（也接受 `39.9,116.4` 直传），以 25km 半径检索，天然规避同名异地；
- **活性过滤**：`datetimeLast` 超过 24h 的站点直接剔除，24h 无结果时放宽到 72h 再试一次；
- **参考级优先**：`isMonitor=true` 的政府参考站在排序中加权靠前。

### 2. 限流与缓存：把 429 当成必然事件而非异常

免费 API Key 每分钟约 60 次请求，多城市并发查询必然触限。客户端做了三件事：

- 优先使用服务端聚合端点（`/hours`、`/days`）而非原始测量流；
- `~/.cache/air-chart/` 下按请求哈希建文件缓存（小时级 20min TTL、日级 2h TTL），缓存命中时整图生成 < 0.5s；
- 429 时按 2s 起步指数退避（上限 30s），并区分 `AUTH_ERROR` / `API_ERROR` / `RATE_LIMIT` 三类失败，各自给出可操作的提示。

### 3. 数据清洗：缺失是信息，不是零

`data_transform.awk` 的三条铁律：

- 负值（传感器校准漂移）与超物理上限尖峰（如 PM2.5 > 2000 µg/m³）直接剔除并计数；
- 时间槽缺失时**保留刻度、标记为空**，渲染层折线断开——严禁填 0，因为 0 会同时扭曲趋势形态并拉低均值；
- 横坐标用 API 返回的站点当地时间（`datetimeFrom.local`），避免 UTC 直接作图导致早晚高峰错位。

### 4. 渲染：200 行 awk 画一张专业图表

`render_draw.sh` 不依赖任何图形库，直接计算坐标输出 SVG：

- Y 轴从 0 起（柱状图强制要求，折线图同样适用，避免视觉夸大波动）；
- 刻度取 1/2/5×10ᵏ 的"整数友好"步长；
- WHO 24h 基准线：达标绿色 `#10B981` / 超标红色 `#EF4444`，`dasharray="4,4"`，标签带数值与单位；
- 配色对齐 openaq-explorer：指标专属色（PM2.5 `#E65100`、PM10 `#6A1B9A`、O3 `#0277BD`、NO2 `#00838F`），多城对比用色盲友好四色；
- 单位防御：站点单位与字典默认不一致时（ppm vs µg/m³），Y 轴用实际单位、WHO 线自动隐藏——宁可不画，不可画错。

## 三、Agent Skill 封装：让模型"会用"比"能用"更重要

SKILL.md 不是 README 的复制，而是写给 Agent 的**操作契约**：

- **触发条件**写进 frontmatter 的 `description`（"当用户要求查看/对比城市空气质量、生成空气质量图表时使用"），这是各平台路由 Skill 的唯一依据；
- **参数表 + 模式自动判定规则**，模型不需要读源码就知道"多城只能单指标"；
- **输出解读规范**：要求 Agent 展示 SVG 路径、注明物理浓度而非 AQI、说明 WHO 线含义；
- **异常对照表**：每个退出码对应一句给用户的自然语言解释，个别城市失败时降级出图而非整体失败。

工程上还做了两件"小事"：凭证分层（`OPENAQ_API_KEY` → `~/.config/air-chart/config` → `~/.air-chart.env`），免费公共服务凭证不进系统钥匙串；30 组边界用例（生僻城市、坐标、非法参数、全指标遍历、错误路径）固化为 `tests/battery.sh` 并接入 CI。

## 五、结语

Agent 工具链的价值不在于"能调 API"，而在于把**领域知识**（站点优选、WHO 阈值、量纲防御、断点语义）固化成管道的一部分，让每一次自然语言查询都得到一张不需要二次解释的图。零依赖不是炫技——它决定了这个 Skill 能否在任意一台裸机、任意一个 Agent 沙箱里被即刻唤起。
